CPU package power and upward history (io18, Linux):
Options > CPU > show_cpu_power enables CPU package watts plus an upward-only
CPU/power dot history. CPU load uses 0-100%; package power uses a separately
labelled watt range, rounded up to the next 50 W for the visible history.
Colours distinguish usage and watts. Narrow graphs retain the ordinary single
CPU history and show watts in the MHz table footer when space permits.
No extra CPU rows are allocated. Disabling power restores cpu_single_graph,
cpu_graph_upper/lower and the configured lower-graph orientation.

Watts are the sum of RAPL package energy changes over measured steady-clock
elapsed time, not instantaneous peak power or wall-socket power. Package
subdomains, DRAM and psys are excluded; aliases are deduplicated. The collector
handles counter rollover, rejects resets and implausible jumps, and rebaselines
after missing data, package changes, pauses or read failures. Missing/denied
readings show --W and leave gaps; a measured zero is displayed as 0.0W.

Kernel ABI: https://docs.kernel.org/power/powercap/powercap.html
Only name, energy_uj and max_energy_range_uj are read. Nothing writes energy,
limits, governors, online state or driver controls. Many Linux installations
make energy counters readable only by root. Run btop as your ordinary user;
an administrator can grant narrowly scoped read access if desired. Such a
sysfs permission change normally expires at reboot. Normal btop installation
adds no permission rule or service; the optional prepare_cpu_power_access.py
helper prepares a rule for explicit administrator installation. Power defaults
to off and existing preferences are retained on upgrade.

Set cpu_single_graph=True for a regular upward CPU usage history without
power. cpu_invert_lower=False also disables the inverted lower view if that
lower graph is explicitly enabled again. A regular upward CPU graph works independently of the optional watts view;
live watts remain off by default until explicitly enabled.

Zram compression (io8; idle hiding added in io9, Linux):
The Nova profile enables a compact three-row footer beneath RAM metrics when
a zram device has workload data and the panel has sufficient space. It appears
automatically when used and disappears again when idle, restoring RAM graph
rows without changing the saved preference. For swap devices, /proc/swaps Used
distinguishes real workload pages from the tiny nonzero compressed swap header.
Other initialized zram devices use original data size to determine activity.
Shift+Z or Options > MEM > show_zram toggles it. Later choices persist across
upgrades. The footer reuses memory-graph rows; it leaves memory/network panel
heights and the full-width mount table unchanged. It works with swap hidden.

ZRAM shows the selected algorithm and logical device capacity (cap), summed
across devices when necessary; mixed algorithms are identified as mixed.
Data shows uncompressed bytes > compressed bytes, followed by the compression
ratio. RAM shows the kernel's mem_used_total, including allocator fragmentation
and metadata overhead. Save is original data minus that reported RAM cost;
negative values mean allocation overhead exceeds the small stored payload.
Sizes follow base_10_sizes, using compact B/K/M/G labels to fit the RAM column.
A zero compressed-size denominator shows --.
Missing or malformed statistics show -- rather than a fabricated zero or ratio.
Known-idle swap devices stay hidden even when compression counters cannot be
read. Devices with unknown activity retain the unavailable-data summary.

The footer is hidden whenever no swap pages are in use. Logical zram capacity
is not RAM preallocated for compressed payload. The footer is useful under memory pressure:
actual stored data, compressed size and allocation cost show its effectiveness.
The original RAM figures already account for this allocation; Save should not
be added to the displayed Available value.

The collector only reads /sys/block/zram*/disksize, comp_algorithm and mm_stat
plus /proc/swaps. No zramctl subprocess, elevated privileges, zram configuration
changes, writeback, compaction or induced swapping are needed. Kernel ABI:
https://docs.kernel.org/admin-guide/blockdev/zram.html#stats
